Highlights
  • cve_fix [images]: A potential denial of service vulnerability existed where a malformed image digest could cause a panic when computing referrer GC labels. The logic is now hardened to validate the digest and skip malformed ones. (20a3b31390653d7a83fdaeb0c318b01a263c9d9a)
  • cve_fix [remotes]: A path traversal vulnerability allowed specially crafted image references containing `..` to rewrite the host component. The reference parser now rejects such paths. (6b631559bd8fa7cd368ad0db7d97b1b46c2e0457)
  • cve_fix [content, remotes]: A denial of service vulnerability was possible due to unbounded reads in the content and remotes packages. Reads are now bounded to the expected size to prevent excessive data from being processed. (91f62bdd77e8851fbc6153013b52c25d2badf80e)
  • cve_fix [build]: The Go toolchain was updated to go1.26.9 / go1.27.2, which includes 15 security fixes for vulnerabilities in packages such as net/http, crypto/tls, and cmd/go. (9c06c813e23fc4082c2fcc2a97cf18f40406f71d)
  • behaviour_change [runtime]: The default seccomp profile was hardened to use an allow-list for socket(2) domains, blocking unknown or future address families by default. This matches a similar change in Moby's default profile. (7936ee5789f2e915ad9f3d2bed5493e4dd28378b)
  • behaviour_change [cri]: The CRI implementation was hardened to not follow symbolic links for container log files, preventing potential log data exposure or manipulation. (098de667dd0b4e83dc135f87420f55a4f05a190d)
  • bug_fix [remotes]: Fixed excessive memory usage during image pulls by throttling chunk buffers, preventing a situation where a fast registry could cause chunks to accumulate in memory faster than they could be written to the content store. (6a78f854af4ba1366fb95f0d66324e3e10e250d1)

  • CVE-2026-56866 (medium) — affects go: net/http: An HTTP/1 client transport could desynchronize a connection after a rejected CONNECT request, leading to potential response poisoning in reverse proxies.
  • GO-2026-6238 (medium) — affects runc: The bundled runc binary was updated to v1.5.2. This version switches from cilium/ebpf to a different implementation for managing cgroup v2 device rules, mitigating an issue in the cilium/ebpf library.
